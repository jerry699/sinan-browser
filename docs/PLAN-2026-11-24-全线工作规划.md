## 四、方向 3（办公 Agent 结合）：升级为销售协同项目

**背景（2026-11-24 用户补充）**：用户在做**阿里云销售**——与**千问办公、workbuddy** 这类产品结合是实打实的卖点。方向 3 从"技术评估"升级为"业务协同"。

**结合形态设想**：
- **司南作为 MCP 服务器**暴露本地能力：历史语义搜索、页面内容读取、蒸馏笔记库、标签整理——千问办公/workbuddy 的 Agent 经标准 MCP 调用（阿里系 Agent 生态正在拥抱 MCP）
- **反向喂给**：Agent 把会议纪要/待办清单喂给司南整理（复用 W5 管线）
- **端云分级叙事**：本地小模型处理隐私内容 + 阿里云百炼/千问处理重任务——正好是阿里云销售话术，且模型本就从 ModelScope 下载，生态叙事自洽

**实施约束**：
1. **司南已定型**：MCP 以**独立 sidecar 组件**形态落地（不进司南核心，不动定型代码），或等 0.4.x 窗口
2. 硬红线不变：每个工具单独授权、默认全关、用户可见的连接管理界面
3. **第一步（12 月）**：最小 MCP server 评估——只暴露"语义搜索 + 页面蒸馏"两个工具，用千问办公/workbuddy 实测调用链路；这同时是给客户的演示 demo
