# W5 设计稿：收藏夹智能整理（含训练闭环）

> 状态：设计稿（2026-11-24 规划，12 月实施）。前置阅读：[TRAINING-PLAN §11.1](TRAINING-PLAN.md)、
> [ROADMAP 三方向](ROADMAP.md)。原则沿用司南两条铁律：**预览确认 UX**（书签是多年沉淀，AI 只建议、用户拍板）
> 与 **设计即含训练闭环**（用户的每一次接受/纠正都是训练对）。

---

## 一、任务定义

收藏夹（书签）智能整理 = 两个子任务，恰好映射司南已验证的两个协议：

| 子任务 | 输入 | 输出 | 司南对应 |
|---|---|---|---|
| **打标签** | 笔记标题 +（可选）首行摘要 | 2-4 个中文标签 | TidyTitles（命名协议） |
| **分组归档** | 一批书签（标题+URL 域名） | 逐项指派到文件夹（可新建文件夹名） | TidyTabs 逐项指派协议（实测零错组） |

数据结构天然同构：**书签 = 标签页，文件夹 = 分组，用户手动整理 = 教学**。

---

## 二、UX 流程（预览确认，三步）

```
① 入口：书签面板右上「智能整理」→ 选择范围（全部/单文件夹/未整理书签）
② 预览卡（关键！）：列表呈现 AI 建议
   - 打标建议：书签名 → [标签1] [标签2]（灰显为"新增"，已有标签隐藏）
   - 分组建议：书签名 → → 文件夹名（新建的文件夹带 ✨ 前缀）
   - 每行左侧 ✓/✕ 可单独否决；顶部「全部接受」
③ 应用：接受的建议一次性执行；底部 Toast「已整理 N 条 · 撤销 ⌘Z」
```

- **⌘Z 全量撤销**（同 Tidy）：应用前的快照整体回滚
- **训练信号采集点（每个都记）**：
  - 接受的建议 → 正训练对（AI 对了）
  - 否决的建议 → 负样本（AI 错了，不学这个映射，记录为困难例）
  - **用户改了标签/文件夹名再接受 → 最强训练对**（人工纠正，权重最高）
  - 用户手动移动书签到文件夹 → 同 Tidy P5 的 moveItems 教学

## 三、推理设计

### 3.1 模型分工

| 任务 | 模型 | 理由 |
|---|---|---|
| 打标签 | Qwen3-1.7B（司南已验证 6/6 命名基准） | 需要语言知识，1.7B 质量档 |
| 分组归档 | obsidian-v1 微调（Phase 3 产物）或 1.7B + 逐项指派提示词 | 微调学"你的分组习惯" |
| 摘要（已有任务） | 1.7B | 沿用 |

### 3.2 提示词协议（逐项指派，司南实测零错组格式）

```
把以下书签逐条归类。已有文件夹先复用其名（精确匹配才归入）：
你的归档先例：
0: 「AI 笔记」→ AI整理/
1: 「旅行攻略」→ 旅行/
书签：
0: 刺猬索尼克3 观后感
1: 东京五日行程表
2: 视频剪辑软件对比
只输出 JSON：{"items":[{"i":0,"folder":"影评/"},{"i":1,"folder":"旅行/"},
{"i":2,"folder":"工具/视频剪辑/"}]}，每条一条，不许遗漏。
```

GBNF 可选约束（llama-server `json_schema` 参数），Phase 2 后期下沉。

### 3.3 记忆层（P5 同构）

- `bookmark-prefs.json`：标题→文件夹 的用户习惯（accept 即记录，⌘Z 即 retract）
- 域名规则复用司南 P5-L2：同域书签两次进同文件夹即成规则，AI 前先**确定性预归档**，模型只见未知剩余
- 记忆可视化/清除：设置 ▸ AI ▸ 记忆管理（同司南 Max 面板的治理原则）

## 四、训练闭环（v5 任务卡：`bookmark-organize`）

### 4.1 数据源（三层，全部零人工）

| 层 | 来源 | 对数（预估） |
|---|---|---|
| L1 使用中采集 | 用户接受/纠正的整理建议（上面 §二③） | 持续累积，每条都是真值 |
| L2 库内挖掘 | 已整理的书签：`(标题, 文件夹路径)` 天然对 | 数百-数千 |
| L3 合成增广 | 标题扰动（同音字/繁简/截断）模拟 ASR/输入噪声 | L2 × 3-5 |

### 4.2 训练配置

- 底座：Qwen3-0.6B（快）或 1.7B（质量）；QLoRA r16；3 epochs
- 数据格式：与 train-v3/v4 相同的 messages 结构（system + user + assistant）
- 评测：**held-out 协议**（seed 独立样本永不入训练，同 v4 教训）
- 验收：held-out 分组准确率 ≥ 60%（0.6B）——对照 v4 纠错的 18% 起点，分组任务更结构化、预期更高

### 4.3 与司南管线的复用关系

| 训练栈组件 | 来源 | 改动 |
|---|---|---|
| 数据合成 | 司南 `gen-correction-data.py` | 改造为 `gen-bookmark-pairs.py`（输入=书签导出） |
| 训练脚本 | 司南 `train-v3-sft.py` | 仅改路径/超参，结构不变 |
| AutoDL 制度 | `sinan-train` 镜像 + 铁律 | 原样复用 |

## 五、实施切分

| 阶段 | 内容 | 依赖 | 工作量 |
|---|---|---|---|
| W5-a | 打标签功能（UX + 提示词 + 记忆层，先用 1.7B） | 无 | 1 天 |
| W5-b | 分组归档（逐项指派协议 + 预览列表） | W5-a | 1 天 |
| W5-c | 训练闭环采集（§二③ 三类信号落盘） | W5-a/b | 0.5 天 |
| W5-d | obsidian-v1 微调 + 接入 | 实例会话 + W5-c 数据 | 半天实例 |

**不做**（沿用司南定型哲学）：AI 不自动执行任何移动/删除；不建云端同步；不打赏反馈闭环。

---

## 六、与三方向的交汇

- **方向 2（训练）**：W5-c/d 就是训练闭环本体，bookmark-organize 进 v5 任务卡
- **方向 1（兴趣摘要）**：同一套 UX（建议列表 + 预览确认）可复用为"订阅更新简报"的卡片骨架
- **方向 3（MCP）**：若 Obsidian 控制台未来接 MCP，整理能力即一个 MCP 工具（`organize_notes`），授权模型同司南红线
